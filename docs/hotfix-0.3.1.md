# 0.3.1 修复与目录整理

2026-10-06，按用户提供的实际错误截图修复文件导入、工作区选择和软件图标，并整理当前项目。

## 修复

- 文件选择器的 `OPENFILENAME` 结构包含不能直接封送的 `StringBuilder` 字段，导致选择器尚未显示就报“无法计算有意义的大小或偏移量”。未使用的文件标题字段改为原生指针，x64结构大小152字节；实际验证打开中文文件、多选导入、另存为路径。
- 工作区改用系统文件夹选择器，可直接输入目录路径，取消正常返回。COM资源与返回字符串按所有权释放，未建立持久工作区。混合导入文件与目录时保留文件，并加载所选目录。
- 从现有叶片矢量生成16、24、32、48、64、128、256七种尺寸的ICO，嵌入EXE的Windows图标资源，同时设置真实窗口图标。通过Windows关联图标提取和窗口测试核对；根目录快捷方式引用当前EXE图标。

## 整理

当前程序集中在 `app/`，最新ZIP在 `release/`，0.1/0.2/0.3历史版本连同原有内容移入 `release/archive/`；根目录保留启动入口。截图集中在 `artifacts/ui/`，采样记录在 `artifacts/metrics/`。删除可重建的包下载副本和乱码构建产物，保留已解压依赖、源码、设计稿和历史记录。目录说明见 [项目目录](project-layout.md)。

独立审查指出两项脚本问题，并已用实际回归复现后修复：清理路径需要检查父目录和递归内容中的目录链接；发行包不能直接压缩可保存个人内容的运行目录。清理现拒绝重解析点，发行包从新建的明确文件清单生成，并保留运行目录中额外保存的文件与已有示例修改。

## 验证

完整 `scripts/test.ps1`：37项核心文件、28项实际WPF窗口/预览、4项真实系统选择器和3项整理/打包回归，共72项通过。截图中的封送错误、混合导入遗漏、父目录链接越界、递归目录链接以及ZIP夹带运行目录个人文件均有观察到的失败后通过记录。

WebView2测试在受限沙盒中曾显示“页面未能加载”；相同构建在正常Windows子进程环境中完整通过。未据此修改原本正常的预览实现。测试仅操作自有临时样例和本测试进程的窗口，不操作用户的其他窗口或文件。

当前 `app/轻页.exe` 实测：暖启动中位数341ms，普通文本关闭40ms，空白工作集83.3MiB，稳定闲置CPU三次采样均0.00%；1/10MiB文本启动至就绪378/443ms。单实例转发与最终退出通过。首次观察480ms，未清空系统缓存。详见 [性能记录](performance.md)。

可复用经验：原生Windows对话框字段必须按ABI声明；递归清理不仅要验证字符串路径前缀，还要检查目录链接；可编辑的运行目录不能作为发行包的原始输入。
