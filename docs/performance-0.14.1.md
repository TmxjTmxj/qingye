# 0.14.1 · 内存与运行速度

这轮优化减少常用操作中的重复工作，保留已有文件格式、原位编辑、分栏和终端功能。本地程序与便携包更新为 0.14.1；GitHub 已发布版本仍为 0.13.0。

## 改动

- 第二编辑栏与 Markdown 原位编辑器在首次使用时创建；普通空白启动不再加载 Markdig 程序集。首次使用这些功能时仍需承担初始化成本。
- 单栏中切换相同展示模式的文件时复用布局，继续恢复每份文件的光标和滚动位置。
- 光标与选区变化合并到一次后台优先级的状态栏刷新；编辑中的完整标题刷新只在修改状态发生变化时进行。保存和错误提示会取消排队的普通状态刷新。
- 复用文件图标、字体映射与高亮资源，避免无变化的重绘；隐藏的文件列表等实际展开后再更新。
- 修复异步 Markdown/结构排版尚未完成时提前消费阅读位置的问题。恢复滚动前确认当前文档、内容版本和排版请求仍然有效。

## 同机配对结果

2026-11-02，在同一台 Windows x64 机器，对优化前的本地 0.14.0 二进制与 0.14.1 使用相同探针。两个版本按 AB/BA 顺序交替，各启动六个独立进程；舍弃第一轮预热，分别取其余五轮中位数。以下是批量操作总耗时，不是单次按键延迟。

| 项目 | 优化前 | 0.14.1 | 变化 |
| :--- | ---: | ---: | ---: |
| 窗口初始化 | 457.67 ms | 388.06 ms | −15.2% |
| 空白窗口工作集 | 92.18 MiB | 89.63 MiB | −2.8% |
| 空白窗口私有内存 | 91.21 MiB | 90.32 MiB | −1.0% |
| 打开两个文件 | 121.43 ms | 118.77 ms | −2.2% |
| 切换文件 120 次 | 1741.41 ms | 1029.78 ms | −40.9% |
| 切换期间累计托管分配 | 221.289 MiB | 164.345 MiB | −25.7% |
| 连续插入 400 次 | 330.12 ms | 246.51 ms | −25.3% |
| 插入期间累计托管分配 | 27.337 MiB | 22.016 MiB | −19.5% |
| 移动光标 1000 次 | 321.91 ms | 219.82 ms | −31.7% |
| 光标移动期间累计托管分配 | 18.165 MiB | 13.852 MiB | −23.7% |

空白工作集减少约 2.55 MiB，幅度有限；主要收益来自更少的布局与临时分配。累计分配表示操作期间创建的托管对象总量，不是操作结束后保留的内存。没有强制 GC、修剪工作集或删除功能。

探针窗口在屏幕外显示、正常布局；初始化计时包含构造、显示及首次布局，**不包含进程启动和 CLR 引导**。工作集在布局后约 300 ms 读取。测试使用两个各 2400 行、约 120 KB 的 Python 文本，先切换预热六次；插入和光标移动分批处理 Dispatcher 队列。探针未开启终端、网页或 PDF 预览。数据仅代表本机条件，未清除系统缓存，不代表大文件、首次冷启动或所有机器上的表现。

独立的实际进程启动验收中，五次热启动中位数为 431.7 ms，空白工作集为 88.6 MiB。该验收的计时与探针不同，作为当前版本运行观察，不与上表混合计算加速比例。便携 ZIP 约 1.51 MiB、解压目录约 3.92 MiB，不含系统运行时。

## 复验

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test.ps1
& ./build/bin/PerformanceProbe.exe ./build/perf-fixtures
powershell -NoProfile -ExecutionPolicy Bypass -File tests/ScriptTests.ps1
```

`tests/PerformanceProbe.cs` 使用程序生成的夹具，不读取用户文档；测量程序仅在 build 中，不进入便携包。比较两个版本时，把同一份探针及配置、各自程序和依赖放在独立目录，依次运行，避免与 UI 回归同时运行。该探针供受控同机比较使用，不设固定性能通过阈值。

本机原始配对输出在 `artifacts/metrics/performance-pair-*.txt`，汇总在 `performance-0.14.1-comparison.json`；这些生成材料不进入公开源码和便携包。

全量回归覆盖 64 项核心、64 项界面、4 项系统选择器、多窗口与真实 CMD，以及最近文件、跨窗口位置与草稿恢复专项。新增检查确认空白启动和主题切换不会提前创建延迟组件、文件图标复用、排队状态刷新不会覆盖显式提示。脚本验收核对依赖哈希、打包隔离、逐文件 SHA256 与版本一致性。

终端首次展开仍需系统 WebView2 和 ConPTY；收起后保留会话，以便继续正在运行的 CLI。其额外内存未包含在上述空白窗口数据中；本轮没有改动终端渲染器，CLI 兼容性与既有验收边界见 [0.13 记录](terminal-0.13.md)。
