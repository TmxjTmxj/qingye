# 轻页：快速查看与简单编辑

日期：2026-10-05
状态：用户已审阅并于 2026-10-05 明确要求开始制作；性能目标仍需实测。

整合界面参考：[主界面设计稿](../../design/qingye-integrated.png)。图中示例代码与网页是合成演示内容；实际产品首次启动只显示空白编辑区，定制面板只在用户点击时出现。

## 用户目标与已经确认的偏好

为 Windows 做一个通用文件查看与简单编辑工具。启动和关闭必须快，尽量少占内存与磁盘。用户喜欢已展示的薄荷、暖白、浅紫三版界面，希望把配色、布局和功能整合起来，色系和功能区域位置可以调整。启动直接进入编辑区，不弹项目选择、功能区选择或安装模块向导。专业开发仍使用专业软件。

最新确认：流畅阅读各种文本是第一优先级；默认打开替换为一个文件，额外文件与工作区由用户主动导入。工作区、文件路径列表与内容只存在本次内存中，不记录历史，不恢复会话。外观设置只在用户主动开启“记住外观”时写入。软件可控制自身记录与缓存，不能承诺消除 Windows 自身文件系统或系统组件的所有痕迹。

## 方案选择

采用 Windows 原生 WPF 界面与 AvalonEdit 文本编辑组件，依赖系统 .NET Framework 4.8。网页/PDF/SVG/Markdown 的高级预览通过按需创建的 WebView2 实现，复用系统 Evergreen Runtime。当前电脑已检测到原生编译工具、WPF 和 WebView2；产品不附带开发工具或整套浏览器。

| 方案 | 适用性与取舍 |
| --- | --- |
| 原生 WPF + 按需 WebView2（选择） | 适合 Windows 快速文件工具，文本模式可完全不启动网页引擎，易于复用系统运行环境。 |
| Tauri + 网页编辑界面 | 易做跨平台界面，但基本编辑也会启动网页引擎；本需求没有跨平台要求。 |
| Electron | 网页开发方便，但需要附带浏览器与 Node 运行环境，安装体积不符合本任务重点。 |

AvalonEdit 支持 WPF 和 net462；WebView2 Evergreen 在不同应用间共享运行时。这里只据此选择结构，不预先宣称特定内存或速度数字。

资料：[AvalonEdit 官方仓库](https://github.com/icsharpcode/AvalonEdit/blob/master/README.md)、[WebView2 运行时分发](https://learn.microsoft.com/microsoft-edge/webview2/concepts/distribution)、[WebView2 性能建议](https://learn.microsoft.com/en-us/microsoft-edge/webview2/concepts/performance)。

## 界面与可调布局

- 默认薄荷浅色；另提供暖白、浅紫预设，可调整强调色、编辑字号、字体与自动换行。高对比文字优先于装饰效果。
- 顶部轻量工具栏：新建、打开、保存、搜索、预览、外观/布局。更多操作置于菜单，不填满主工作区。
- 无文件参数启动时立即显示可输入的空白文档；带文件参数启动时立即打开指定文件。首次使用和以后使用都不显示工作区向导。
- 文件标签显示文件名、修改标记、关闭按钮。默认只打开用户本次指定的文件。
- 可选文件列表/目录树、主编辑区、第二编辑区、预览区。平时可只留编辑区；进入网页工作场景可同时显示前端文件、后端文件、网页效果。
- 分隔线可拖动改变比例。面板提供交换左右、改为上下、隐藏/显示；拖动面板标题到可用停靠位置可改变位置。提供“一栏阅读”“两栏对照”“代码与预览”预设和“恢复布局”。
- 默认不持久化；用户主动选择记住外观后，只保存配色、布局比例与编辑偏好。布局设置不保存文件路径、标签列表或文件内容。
- 状态栏显示文件类型、编码、换行、行列位置、只读状态；不摆放未经实测的速度或内存数字。

## 第一版功能范围

| 文件/场景 | 查看与编辑方式 |
| --- | --- |
| TXT、Markdown、日志、任意可解码文本 | 直接编辑；未知文本扩展名也可打开。 |
| HTML、CSS、JS/TS、JSON、YAML、XML、INI、TOML、各类程序源码 | 直接编辑；已支持语言显示语法高亮；其余保留普通文本编辑。支持行号、缩进、撤销/重做、跳转行、选中内容与字符信息。 |
| CSV/TSV | 编辑原始文本；另有轻量表格查看，原始文本仍是保存来源。 |
| SVG | 编辑源码；预览按需开启。 |
| HTML/CSS/JS | 编辑与实时页面预览；支持相对资源、刷新、桌面/窄屏宽度与用户指定的本机开发服务器 URL。 |
| 后端源码 | 可与前端文件同时编辑；预览可连接用户已经运行的本机服务。编辑器不自动启动后端、不内置 Python/Node 或依赖安装器。 |
| Markdown | 源码编辑与排版预览；预览不执行文档脚本。 |
| PNG/JPEG/BMP/GIF 等常见图片 | 原生查看、缩放与适应窗口；此版本不修改图片像素。 |
| PDF | 按需网页内核查看；此版本不改写 PDF 内容。 |
| DOCX/XLSX | 轻量内容查看：DOCX 提取段落文字，XLSX 提取工作表与限定范围单元格；显示“内容预览”，不伪称完整排版。不提供会破坏格式的原文件编辑。 |
| 未支持的二进制类型 | 文件基本信息与限量十六进制查看，可用系统关联软件打开；不把二进制当文本保存。 |

通用操作：多文件打开、拖入文件/目录、新建、保存、另存为、关闭当前/其他/全部、双文件对照、当前文件搜索与替换、大小写/正则搜索、跳转行、自动换行、字体缩放、编码选择、换行选择、只读切换、在资源管理器定位、系统关联软件打开。

编码：优先 BOM 与严格 UTF-8 检测，支持 UTF-8（有/无 BOM）、UTF-16 LE/BE、GB18030。不能可靠识别时提示并允许选择。保存保持原编码、BOM 与已有换行方式；用户主动转换时才改变。读取失败或二进制判断失败不能默默损坏原文件。

目录只在用户打开目录后按层加载；不全盘扫描、不启动项目索引，不递归读取 node_modules、.git 等大目录的内容。

## 保存、关闭与退出规则

1. 不保存会话，不恢复旧窗口，不保留关闭文档的内容缓存；无改动的空白文档关闭时不弹窗。
2. 未保存内容不自动写回磁盘。显式保存、另存为或退出时的保存选择才写入文件。
3. 关闭无改动标签立即释放文档、事件订阅与预览资源。关闭多个标签或退出时，有修改的文件用一个集中处理窗口：逐项选择保存，或一次放弃全部，或取消退出。
4. 若原文件在外部删除：未修改的标签可直接移除；有改动的标签保留本次内存内容，提供另存为/放弃，不自动重建原路径。
5. 若原文件在外部修改：保存前检查文件版本，提供重新读取、另存为或明确覆盖；不静默覆盖外部修改。
6. 保存使用同目录临时文件与替换，成功后才清除修改标记；只读、权限不足、磁盘满等错误保留编辑内容。
7. 隐藏预览会释放网页控件；退出停止本应用的监听器、计时器、文件观察与预览，不留下托盘、驻留编辑器或由本应用创建的浏览器进程。不能终止用户其他程序的进程。
8. 不记录最近打开列表；只有轻量偏好文件持久化。预览临时缓存放在独立目录，随预览结束清理，不用于下次恢复文件。

## 数据流与组件边界

- `DocumentStore`：本次打开的文档、修改状态、编码、原文件版本；文档关闭即移除。
- `FileService`：异步读取、编码判别、保存与冲突检测；不依赖界面。
- `EditorPane`：显示与修改文本、搜索替换；两个编辑区共享对应文档数据，但各自保留光标和滚动位置。
- `LayoutSettings`：小型偏好文件，只有界面与编辑参数。
- `PreviewController`：识别适合的预览器，开启时创建、关闭时释放。图片用原生控件；网页内核与解析器延迟加载。
- `FolderBrowser`：按层列目录；只观察本次用户打开的文件/目录。
- `CloseCoordinator`：统一收集修改文档、处理保存/放弃/取消，处理完才关闭窗口。

静态网页预览从明确选定的文件目录读取资源，并把当前未保存的已打开文本映射到预览；读取范围不能越过该目录。连接用户指定的服务 URL 时，页面内容由该服务负责，编辑器不能声称它会执行任意后端代码。

## 性能与磁盘约束

这些是实现目标，需在当前电脑实测后报告，不是现在已达成的承诺：

- 暖启动至可输入目标 0.5 秒左右；首次启动目标 1.5 秒以内。分别记录多次结果，不用启动进程时间代替界面就绪时间。
- 无改动的纯文本窗口退出目标 0.3 秒左右；开启预览后的进程清理目标 2 秒以内。
- 发布目录目标 15 MB 以内，排除源码、设计图片、编译工具与系统共享运行时。必须同时报告实际应用目录和压缩包大小。
- 文本模式闲置 CPU 接近零；报告实际工作集与私有内存。预览模式单列全部自有进程占用，不把浏览器子进程遗漏掉。
- 1 MB 文本、10 MB 文本、大目录按层展开分别测响应。20 MB 以上文本关闭语法高亮并提示大文件模式；超过安全编辑上限时以每段不超过 4 MB 的方式分段只读，不整份加载到内存。上限先设 128 MB，可按实测收紧。
- DOCX/XLSX 预览单个 XML 条目限 16 MB，总计解压读取限 64 MB；表格最多展示每张工作表前 500 行、50 列，并明确显示截断提示。不能因压缩文件膨胀耗尽内存。
- 预览刷新采用短延迟合并；只有相关文档发生变化才更新，不持续轮询。

## 验收与测试

自动化验证覆盖真正可能造成数据丢失或资源残留的规则：编码/BOM/换行往返、保存失败与外部变更、关闭决策、二进制只读、大文件限制、路径限制、布局偏好不含会话数据。

实际桌面验证覆盖：启动即输入、拖入与打开文件、双文件同时编辑、搜索替换、显式保存、切换三套配色、移动/缩放面板、图片与 Markdown/网页/PDF 预览、删除文件后的关闭、一次性处理多个未保存标签、重启不恢复、退出后无自有进程残留。捕获整合布局与纯编辑布局截图进行设计核对。

发布交付物：可直接运行的 Windows 程序、轻量发布目录/压缩包、源代码、简短操作说明、实测性能与功能限制。没有完成的格式支持要明确列出，不能用演示内容冒充真实文件功能。
